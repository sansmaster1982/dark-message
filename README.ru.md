# Dark Message

Офлайн-шифрование сообщений и файлов для Android и iOS.

Вы шифруете на своём телефоне, отправляете результат тем способом, которым уже пользуетесь —
мессенджером, почтой, передачей файла, распечатанным QR-кодом, — а другой телефон
расшифровывает. Само приложение не выходит в сеть.

[English version](README.md)

---

## Что это

Dark Message — не мессенджер. У него нет серверов, учётных записей, списка контактов и
доставки. Это пара инструментов — зашифровать и расшифровать — плюс место, где лежат ключи.
Всё, что он делает, — обычный текст или обычный файл, который вы переносите сами.

В этом весь замысел: если приложение ничего не отправляет, нечего перехватывать, не с чего
собирать метаданные и нечего изымать вместе с аккаунтом.

**Чего он намеренно не делает**

- Не выходит в сеть вообще. Манифест Android не просто не запрашивает `INTERNET` — он
  удаляет это разрешение явным `tools:node="remove"`, а задача Gradle во время сборки
  разбирает *итоговый* манифест релиза и роняет сборку, если `INTERNET` или
  `ACCESS_NETWORK_STATE` вернутся туда через зависимость.
- Ни регистрации, ни учётных записей, ни номера телефона.
- Ни аналитики, ни отчётов о сбоях, ни рекламных идентификаторов, ни рекламы.
- Ничего не покидает устройство, пока вы сами не передадите это другому приложению.

## Как устроено

Четыре экрана, одинаковые на обеих платформах.

| Экран | Что делает |
| --- | --- |
| **Чаты** | Названный чат — это одна общая парольная фраза. В строке виден отпечаток ключа. |
| **Шифрование** | Текст, фото или документ → base64 в буфер обмена либо файл `.darkm`. |
| **Расшифровка** | Вставить base64 или открыть `.darkm`; результат можно посмотреть, сохранить, передать дальше. |
| **Настройки** | Тема, язык (русский / английский), инструкция. |

У обоих собеседников должна быть одна и та же парольная фраза. Её можно набрать на обоих
телефонах вручную или передать при личной встрече через встроенный обмен по QR: один телефон
показывает код, другой его сканирует, а отправитель называет вслух шестизначный PIN.
Парольная фраза внутри кода зашифрована этим PIN-кодом, поэтому сфотографированный экран без
него бесполезен.

Чтобы убедиться, что на двух телефонах действительно один ключ, сравните **отпечаток** под
названием чата — восемь шестнадцатеричных символов, первые четыре байта `SHA-256` от
парольной фразы. Он ничего не выдаёт о ключе, и произносить саму фразу вслух не нужно.

## Криптография

Намеренно скучная и стандартная, и одинаковая на обеих платформах.

| | |
| --- | --- |
| Вывод ключа | PBKDF2-HMAC-SHA512, **600 000** итераций, случайная соль 16 байт, ключ 32 байта |
| Шифр | AES-256-GCM, случайный nonce 12 байт на сообщение, тег 16 байт |
| Случайность | `SecureRandom` (Android), `SecRandomCopyBytes` (iOS) |
| Хранение ключей | Tink AEAD поверх DataStore (Android), Keychain, `WhenUnlockedThisDeviceOnly` (iOS) |

Парольная фраза хешируется как **сырые байты UTF-8** на обеих сторонах. Это принципиально:
`PBEKeySpec` в Java и `CCKeyDerivationPBKDF` в Apple по-разному превращают не-ASCII пароль в
байты, и русская парольная фраза давала два разных ключа. Теперь обе платформы прогоняют
PBKDF2 прямо по UTF-8-байтам.

### Формат пакета

Файл `.darkm` и его текстовая форма в base64 — одни и те же байты:

```
[версия:1][тип:1][соль:16][nonce:12][шифртекст‖тег:N]
```

`версия` — `0x01`. `тип`: `0x01` текст, `0x02` изображение, `0x03` документ. Для документа
расшифрованный открытый текст оформлен так:

```
[длина имени:2, старший байт первым][имя UTF-8][байты файла]
```

Длина, которая не помещается в открытый текст, означает, что это вообще не кадр с именем и
весь открытый текст — файл; нулевая длина означает, что у отправителя не было имени.

### Обмен ключом по QR

```
darkmessage://chat/1/<base64url без выравнивания>
```

Тело — `kdfId(0x01) ‖ соль(16) ‖ nonce(12) ‖ шифртекст‖тег`, запечатанное AES-256-GCM на
ключе, выведенном из шестизначного PIN теми же параметрами PBKDF2. Дополнительные
аутентифицируемые данные — `"darkmessage-qr-v1" ‖ kdfId ‖ соль ‖ nonce`, открытый текст —
`длина имени(1) ‖ имя(UTF-8, ≤64 Б) ‖ парольная фраза(UTF-8, ≤128 Б)`.

Экраны показа и сканирования выставляют `FLAG_SECURE` и прячутся из списка недавних
приложений, а код скрывается через минуту.

## Структура репозитория

```
android/    Kotlin, Jetpack Compose, Material 3   (minSdk 26, targetSdk 35)
ios/        Swift, SwiftUI                        (iOS 17+, iPhone и iPad)
design/     мастер-файл иконки и скрипт, который режет все размеры для обоих приложений
```

У приложений нет общего кода — у них общий *формат* и набор тестов на каждой стороне,
которые побайтово проверяют одни и те же векторы. Так сделано намеренно: каждое приложение
использует проверенные примитивы своей платформы, а не встроенную криптобиблиотеку.

## Сборка

### Android

```bash
cd android
./gradlew assembleDebug
./gradlew testDebugUnitTest
```

Для релизной сборки нужен ваш собственный ключ подписи. Создайте `android/local.properties`:

```properties
RELEASE_STORE_FILE=/абсолютный/путь/к/вашему.jks
RELEASE_STORE_PASSWORD=...
RELEASE_KEY_ALIAS=...
RELEASE_KEY_PASSWORD=...
```

или задайте те же имена как переменные окружения. `local.properties` в `.gitignore`, и
никакого keystore в этом репозитории нет.

### iOS

Проект Xcode генерируется, а не хранится в репозитории:

```bash
cd ios
brew install xcodegen
xcodegen generate
open DarkMessage.xcodeproj
```

Укажите в Xcode свою команду разработчика. Сторонних зависимостей нет — нечего подтягивать и
некому доверять, кроме фреймворков Apple и этого репозитория.

### Тесты

```bash
cd android && ./gradlew testDebugUnitTest          # 122 теста
cd ios && xcodebuild test -scheme DarkMessage \
    -destination 'platform=iOS Simulator,name=iPhone 17 Pro'   # 91 тест
```

В наборе iOS есть UI-тесты, которые водят по настоящим экранам на симуляторе, и обе стороны
проверяют одни и те же кросс-платформенные векторы — поэтому изменение, ломающее
совместимость, роняет сборку, а не всплывает у кого-то на телефоне.

## Безопасность

**Это не проаудированная криптография.** Это аккуратная и обыкновенная сборка из стандартных
примитивов — PBKDF2 и AES-GCM в том виде, в каком их даёт платформа, — написанная одним
разработчиком, без независимой проверки. Прочитайте код, прежде чем доверять ему что-то
важное. Замечания и исправления приветствуются.

От чего замысел защищает: от чтения сообщения при передаче, от того, что переносчик оставит
себе копию, и от сервера, хранящего вашу переписку, — потому что сервера нет, а переносчик
видит только шифртекст.

От чего не защищает: от скомпрометированного телефона, от того, кто узнал парольную фразу,
от слабой фразы (пользуйтесь генератором) и от того, кто и так видит, что вы с кем-то
обмениваетесь файлами. Скрывается содержимое, а не сам факт.

Нашли уязвимость — откройте issue, а если не хотите делать это публично, напишите на
darkmessageapp@gmail.com.
